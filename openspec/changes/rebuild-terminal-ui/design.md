# Design

## Context

动机与范围见 proposal.md。源基线 main 93d8f3d586ef39c921dce819a164db8eefb18be0；规范基线 PR #1 713e2aeda6b10bb185f2a61c9928d8b5b74aed06。旧目录中有手写 ANSI 和 Unicode 数据，不能作为使用中心仓依赖后的活动实现。当前没有已冻结的新公共接口，也无新框架编译证据。

## Goals / Non-Goals

本轮交付可评审的仓库与后续工程计划。功能实施计划仅描述依赖与验收，不编造尚未验证的语法、类型签名或代码。产品不依赖 Node、OpenSpec、Superpowers；这些只属于开发环境。不得扩展到完整 ArkUI SDK、虚拟终端、JS/TS 运行时或编辑器专用内核。

## Decisions

### D-001：原仓库重建，隔离旧实现

采用根模块主库及 examples/、benchmarks/ 独立项目布局；legacy/ 保留原源码与元数据但从根构建和制品排除。比直接删除保留更多可核对证据；比将新旧源码并存 src/ 避免平行活动内核。用户已明确重新实现，故不为旧内部接口新增兼容层。TASK-001 盘点必要行为，TASK-024 在新交付完整后删除隔离区，不永久维护旧版。

| 路径 | 职责 | 本轮 / 后续 |
|---|---|---|
| src/ | acnl 主库，新内核唯一入口 | 本轮仅目录；后续仓颉实现 |
| examples/minimal/、examples/composition/ | 独立 CJPM 示例项目，引用根主库 | 后续创建 cjpm.toml 与源码 |
| benchmarks/rendering/ | 独立 CJPM 基准项目 | 后续创建并测量 |
| tests/ | 仓库集成/负向语法场景；模块单测按 CJPM 支持存放 | 本轮仅目录 |
| docs/product/ | 安装、语法、API、终端限制、基准方法 | 本轮仅真实状态说明 |
| docs/development/、docs/decisions/、docs/reviews/ | 环境、设计决策及证据 | 开发专用，不发布 |
| openspec/changes/rebuild-terminal-ui/ | 提案、规格、设计和权威任务状态 | CLI 创建目录，本轮完整规划 |
| .agents/skills/openspec-*/ | CLI 生成的 Codex 入口 | 已生成并跟踪 |
| .agents/skills/superpowers | 指向锁定本地工具库的发现入口 | 安装脚本生成，忽略提交 |
| legacy/ | 无活动构建路径的历史参考 | 本轮迁移，后续删除 |

根保留 package 而非 workspace：CJPM 两者不能同存，include/exclude 是 package 规则；根主库 bundle 可将示例和基准项目完整放进同一源码制品。示例/基准的 path 依赖只向包内根目录解析；主库外部依赖必须是中心仓形式。TASK-023 必须实际验证嵌套项目在 bundle 与干净目录可用，不能仅凭规划保证。目录暂不创建空 cjpm.toml 或 Hello World，避免伪成品。

### D-002：中心仓依赖与薄适配

固定 ansies 1.3.113、unicode 0.1.0；来源和摘要见 docs/development/dependencies.md。不直接复制第三方实现、不内嵌旧 Unicode 表。薄适配器负责将框架结构化样式、区域安全和能力策略映射至依赖；不包装全部依赖 API。ansi 生成与终端回复解析能力不等于任意 ANSI 流解析，先做 TASK-003 缺口调查，再冻结受限输入契约。SDK 验证基线 1.2.0，模块标识 acnl 和历史版本号保留，正式版本由发布任务核对占用后确定。

替代方案：继续使用旧代码违背外部依赖选型；直接向业务暴露依赖所有类型将其版本变化扩散到公共契约。选择受控适配边界，具体类型在语法验证后定义。

### D-003：语法先证据，能力按切片落地

先调查组件块、链、状态、条件/列表、自定义组件与回调的真实编译路径。语言现有能力/宏优先，仓颉前端仅在证据表明必要后比较；不预先锁定未经验证的宏实现。调查结论是独立交付物，调查之后才冻结精确接口与实现任务卡。后续依赖方向为构造前端 → 节点与绑定 → 布局/绘制 → 合成帧 → 差分 → 输出适配；业务组件不写终端。

TASK-001 还须调查目标 OS、TTY/非 TTY、终端输入、raw mode、resize 与模式恢复形成支持矩阵，TASK-004 冻结产品支持边界。当前 Linux x64 CI 是初始验证宿主，不意味着擅自排除 Windows/macOS，也不构成对这些平台已支持的承诺。

### D-004：单一规划与渐进 L3

OpenSpec 1.14.3 CLI 实际生成目录和六个 Codex 技能，Superpowers 锁定提交作为开发依赖。方案/计划分别归入 design.md、tasks.md，覆盖技能默认 docs/superpowers 路径；不保留两套设计与任务。近期调查任务定义完整，远期工作按已知验收拆为 L3 候选但保持 planned；其接口依赖未冻结，DQ 不得虚记 pass。本轮明确不 apply 产品变更。

### D-005：发布白名单与双层 CI

cjpm.toml include 限定 src、examples、benchmarks、docs/product 和许可证等，exclude 显式排除开发资料。根 README 是产品入口，不链接仅源码仓库才有的开发文件。CI 分为静态治理作业与检测到新源码后的产品作业；产品作业安装固定 SDK，切片模式构建测试主库与当时已引入的示例/基准；最终发行模式才要求全部项目齐备、执行基准并 bundle，检查实际 cjp 清单。规划阶段产品作业跳过，输出明确状态；主动运行产品入口在未实现时失败。

不自动 publish：本轮只配置发布边界，不执行对中心仓的写入。GitHub 自动源码 zip 不受 cjpm.toml 控制，不作为产品发行制品。未授权修改分支保护或仓库权限。

## Risks / Trade-offs

- ArkUI 语法能否完整实现未证实 → TASK-002 交付可复现编译证据，失败不得静默降级。
- SDK 官网下载可能需要登录或受限网络 → 自动安装校验固定摘要，允许同内容可信镜像；失败显式阻塞，不假装安装完成。
- 依赖声明不是可用性证明 → TASK-003 验证 API、字符策略、增量解析缺口与传递许可证。
- 保留旧版本号可能已被中心仓占用 → 本轮不发布，TASK-023 发布前核对并确定新版本，不能覆盖已有制品。
- 制品包对嵌套 path 依赖的处理尚需实际确认 → TASK-023 干净解包验收；失败时修改封装方案，不少交付示例或基准。
- CI 首次运行可能受仓库 Actions 策略限制 → 记录远端真实状态；本地检查通过不能替代 Actions 成功。

## Migration Plan

本轮 PR 基于三份治理文档，迁移历史源码、建立开发环境与发布/CI 配置，供评审但不合并。可通过回退本 PR 恢复旧布局，不操作真实用户数据。后续授权后先执行调查任务，冻结接口，再分切片实现；每个切片同时交付对应验证与文档，最后集成 U1–U5、制品、基准及退役检查。全部必需证据满足后方可归档产品变更。
