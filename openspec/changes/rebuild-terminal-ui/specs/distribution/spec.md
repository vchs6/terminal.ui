# Spec Delta

## Purpose

规定使用者拿到的源码制品必须完整并可以离开开发仓库使用，同时明确开发治理文件的排除边界，避免将历史实现、开发工具、审查记录和凭据混入产品交付。

## ADDED Requirements

### Requirement: 产品范围

发行制品 SHALL 包含主库源码、独立示例与基准项目、产品说明、许可证和必要归属信息；制品内项目引用不得指向包外开发目录。

#### Scenario: 解包后使用

- **WHEN** 最终制品在干净目录解包
- **THEN** 可按产品文档构建主库、运行示例和基准，无需开发治理工具。

### Requirement: 开发资料隔离

CJPM 配置 SHALL 使用 include/exclude 限定产品范围，排除治理规范、OpenSpec、Superpowers、开发文档、CI、历史源码、构建缓存及凭据；实际 bundle 清单必须复核。

#### Scenario: 防止开发文件泄漏

- **WHEN** 生成待发布的 cjp 包
- **THEN** 仅包含允许路径；发现开发文件、包外路径、缺少必要项目时阻止交付。

### Requirement: 未实现不得发布

项目 SHALL 区分规划检查与产品验收；主库、示例或基准未实现时不得生成可发布通过结论，不能以目录存在或空测试通过替代验收。

#### Scenario: 规划阶段

- **WHEN** 本轮 CI 成功但 src 无框架实现
- **THEN** 只报告规划与仓库检查通过，产品构建/发布仍不可用。
