# 独立开发检出设计

## Context

基线 `61e25f009f8f26c991c3f2ba758987db83bedc4a` 同时承载产品源码、活动流程和迁移原件。用户授权清理当前树并提供可重建的依赖清单。清理范围由决策 CLEAN-D01 冻结，审查和执行证据见[记录](evidence.md)。

## Goals / Non-Goals

- 检出具备现行开发、消费、集成测试和 Linux 任务接续所需源码及输入。
- 官方依赖可由普通包管理和既有构建入口重建，首次运行保留实际下载和校验失败信息。
- 历史证据通过固定提交恢复。产品行为、公开契约、历史提交及原工作区受现有治理约束。

## Decisions

- 普通向前提交配合保留祖先的 blob 过滤克隆。完整克隆会下载大历史对象，浅克隆缺少交互 C 准入检查所需祖先，重写历史会破坏历史证据入口与已下载克隆的同步。
- 活动证据的权威定位在消费者侧。交互 C 使用根相对夹具与八个已接纳祖先，颜色 oracle 使用固定原始源码夹具和 SHA-256。原证据及断言的含义沿用历史版本。控件与主题 runner 使用调用者配置的 SDK、stdx 和可选 UCD；bundle 验证在新输出目录中使用独立 cache。
- 历史 Markdown 链接指向固定旧提交中的真实文件或归档清单。长期开发入口集中在 docs/development。归档恢复工具仍可对含原 catalog 的检出和其自身合约测试运行。
- C008 当前输入随源码保存，其历史实机结果继续由原验收记录限定。尚缺的主机环境按对应任务契约准备。

## Risks / Trade-offs

- 删旧树前按固定摘要确认测试输入及独有在途成果。若发现当前消费者需要更多历史数据，按已验证的最小输入范围迁出。
- 默认 filtered clone 保存提交祖先。服务端不支持过滤时下载量可能增大，首次构建还需访问锁定的上游下载服务。
- 历史缺完整链接的成员经归档目录索引定位。恢复操作使用固定旧提交或相应归档，避免加载全套旧卷。
