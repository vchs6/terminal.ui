# Design

## Context

变更动机见 [proposal](proposal.md)。基线 b8ce41857e37186cadfbbbc3586a9f8f5e67ece4 没有框架源码；本轮修订的是需求契约，不是已发布接口迁移。用户已确认总体草案，并授权必要验证、独立审查及完成后直接推送 main。版本使用三段数字，当前产品开发版本0.0.0；第三方版本不重置。

文本终端以行列/字符簇及键盘为基础。真实图形宿主、系统剪贴板、标题和图片图标均不是基础假设。核心需求权威为 docs/requirements.md；OpenSpec 是场景投影。各产品验收仍 pending，本轮文档和探针审查不能改变这一事实。

## Goals / Non-Goals

**Goals:** 把已确认行为转为稳定需求、可判定场景和任务映射；以实测决定尾随 Lambda 与字符依赖路线；明确持久节点、失效、主题与宿主能力的责任及失败语义。

**Non-Goals:** 本轮不编写产品框架/示例/基准，不冻结尚未通过产品集成的精确 API，不执行发布；不实现 CSS、GUI、PTY、运行时源码解释器、业务状态注册框架或命令行一次性输出。已有独立文件快照继续保留。

## Decisions

### D-009 — 持久节点＋可重算描述（用户已选择）

对比重量持久视图对象包揽所有职责、每帧重建纯绘制描述、持久节点＋轻量描述三条路线。选择第三条：持久节点保存身份/交互/订阅，描述保留可重算属性，绘制模型与设备隔离。避免普通重算丢失焦点、撤销记录或重新创建业务对象；代价是需要明确协调和卸载契约。

业务数据/排序/保留策略归业务；视图拥有组件组织、顺序与显隐；框架执行节点变更和渲染。描述与动态 API 共用同一子序列，不隔离成动态专用容器。只改变明确定位的节点；父卸载释放全部附属节点。API 不按数据通知推断业务数据保留。结构操作在 UI 批次执行，冲突及无效引用诊断由 TASK-004 冻结并由 TASK-032 验收，不用重复节点树兜底。

### D-010 — 原生尾随 Lambda 优先，宏只补已证实缺口（工程决定）

用户指出尾随 Lambda，官方文档也明确其可表达 Column/Row 层次。比较：原生调用＋构造上下文、宏生成、独立前端。首选原生能力，保留类型检查和仓颉回调；宏是否必要按绑定和源码诊断证据判断，暂不引入独立前端。

尾随块只是函数参数，不自动收集子表达式，也不自动追踪状态依赖。R5 隔离探针分别验证正例、负例和初值/闭包差异，不能把演示容器称为完整 ArkUI 或产品API。实际 SDK 1.2.0 不允许逃逸闭包捕获可变局部 var；已验证替代为捕获 let 绑定的业务/状态对象，更新其字段。精确构造语法仍需 TASK-002/004 的完整验收。

### D-011 — 单一 UI 调度与两种更新入口（用户已确认）

响应式状态和显式定向通知都产生失效，收敛到 UI 执行域。小数据自动依赖失效，大数据/长任务在合适时间提交通知；通知指向绑定/节点及内容、状态、布局或结构，框架扩展连带范围并合批。后台不无同步修改树/缓冲；任意普通变量变化不保证自动更新。状态可由组件默认管理或由视图绑定控制，同一状态只有一个权威值。

### D-012 — M1/M2（用户已确认）

M1 完整目标帧＋差分输出，作为可用基础和独立对照；M2 脏节点与区域追踪，局部布局/绘制后仍差分。相比一开始全面实现局部算法，分阶段降低宽字符/遮挡/恢复错误；相比永远完整帧，M2 必须证明内部工作量改善。公开 API 不随里程碑改变。

局部失效包含内容、样式、尺寸、结构、视口，扩展旧新绘制区域、阴影、相邻布局依赖及暴露底层。resize 和全局影响可全帧失效。M2 验收使用 M1 帧对照、负载及工作量/CPU/内存/输出记录，不设无依据绝对 FPS。大列表只绘制可见内容的策略不改变业务排序或要求复制全部数据。

### D-013 — 实际尺寸优先与键盘基础（用户已确认）

布局使用实际行列，在可满足时遵循最小尺寸，空间不足时按实际尺寸收敛；不强制放大、不自动隐藏，不把大最小画布作为默认。横纵分区支持固定/内容/比例，纵向滚动为主，表格横向与输入内部光标视口为例外。

归一化键盘事件优先于快捷键封装。组件→父链→当前输入域应用处理器，拦截可阻止默认；模态未处理也不穿透下层。单行 Enter 提交，多行换行，提交快捷键由应用定义。Unicode 编辑按字符簇，不承诺字体、完整 IME 或未知终端全部键位。多行粘贴到单行输入默认拒绝整个含换行片段并报告原因，应用可显式预处理后提交，不逐换行误触提交。系统剪切只在复制确认成功后删除选区；sent_unconfirmed 默认保留选区并返回结果，应用可显式决定继续剪切；撤销记录不因失败或未确认复制而改变。此保守默认不伪造剪贴板成功。

### D-014 — 分类主题单文件 TOML（方向已确认，格式为工程决定）

用户确认分类配置、四主题、应用控制重载。比较单文件 TOML、跨文件继承、完整 CSS：首版单文件＋变量/命名样式；不支持外部 extends/include、脚本或选择器。未来确有重复维护需求才重审，避免为有限终端属性构建复杂引擎。

按属性：显式属性 > 复用样式 > 主题 > 默认；同来源活动状态逐属性 disabled > selected > focused > normal，允许选中前景与聚焦边框同时存在。未设置回落，显式复位取框架默认。候选整套校验后原子替换，失败保留旧主题；应用显式加载/切换/重载，不默认监听。请求以应用发起顺序分配版本，完成较晚的旧请求不得覆盖已接受的新请求。主题只负责外观，不改变业务状态或显隐。字段类型、依赖、资源上限的精确契约归 TASK-004/025，不能用说明示例冒充产品可加载配置。

### D-015 — 核心字符能力与可选宿主适配（用户已确认）

剪贴板目标是用户本地设备，包括 SSH。通过支持的终端通道复制，粘贴接收本地终端事件，不主动读取剪贴板、不调用远程系统剪贴板冒充本地。标题与实际图片图标分开，OSC1名称和界面内图片均不满足图片图标要求。未验证适配器则明确 unknown/unsupported。

能力状态与操作结果分开；写出字节不是已生效。缺失可选能力不能阻止核心运行；真实 I/O 失败若破坏输出同步仍按统一失败契约处理。参数校验防控制注入；恢复只承诺已保存、由框架修改且有恢复通道的状态。不能承诺任何文本终端都有图片图标协议。

### D-016 — 外部字符算法选型（本轮用户授权评估）

原先固定unicode单库未经运行验证，用户新增unicodewidth候选。比较unicode独用、unicodewidth独用、按职责互补。R5初步实测：unicodewidth宽度策略较符合CJK/emoji目标但无分段；unicode可分段但存在原生数据构建依赖、空串迭代和部分emoji宽度差异。选择unicodewidth作为唯一显示宽度来源，unicode用于分段/规范化；不调用unicode宽度作为互相兜底的第二算法。

这是有代价的互补，而非声称即插即用：原生数据构建、宿主构建工具和许可须在正式依赖集成任务复现，空簇须在适配边界过滤。探针成功只覆盖记录样本，不能代替全Unicode测试。若干净制品无法携带并构建依赖，相关任务保持阻塞；不得手写平行Unicode内核掩盖缺口。ansies仍只使用实际受支持编码/解析能力，富文本和键盘解析缺口单独登记。

## Risks / Trade-offs

- 原生语法不能覆盖全部 ArkUI 习惯 → 保留必需块＋链，逐项验证，宏仅补证实缺口；不偷偷退化为配置对象。
- 局部重绘漏掉遮挡/宽字符 → M1完整帧路径与独立预期保留，M2必须对照。
- 混合节点操作冲突 → 按父/身份/批次明确责任和诊断，不推断业务保留。
- 多依赖与原生数据构建扩大部署成本 → 锁定来源/摘要/传递许可，独立干净构建验收，不把探针二进制打入制品。
- 主题竞态和坏文件 → 原子校验替换、旧请求不能覆盖新请求，失败保留状态。
- SSH/终端拒绝剪贴板或图标 → 报告能力及确认程度，不把可选特性列核心启动条件。
- 引用主线源码漂移 → 调研为参考，技术结论以本轮固定源码、命令和摘要为准，不宣称横向性能排名。

## D-017 — Cross-platform and HarmonyOS amendment

用户已明确新增跨平台和鸿蒙OS。工程细化采用Linux、Windows、macOS、HarmonyOS四目标矩阵，共用平台无关核心及视图源码，每OS独立会话适配；不按OS复制UI、不将POSIX封装作为全平台保证。具体目标版本/架构/SDK/终端宿主经TASK-001/004冻结，至少一个有效配置覆盖每个必需OS，缺目标不能声称跨平台完整支持。OpenHarmony单独记录，不冒充商业HarmonyOS验收。

本轮只修改规格并核对官方资料。鸿蒙SDK/hdc/交叉编译信息只能证明其自身能力，不证明应用沙箱具备交互TTY/键盘/resize通道。合法终端宿主缺失是实现前阻塞，不能偷偷降为仅日志、仅远程Linux或改成GUI后端。各目标的unicode原生数据/归档/链接需独立构建消费验证。

替代方案为延续Linux特化或复制平台UI，均不满足统一公开构造目标；选择现有平台输入/输出边界延伸为平台后端。TASK-038–041分别承担Windows/macOS/HarmonyOS/Linux后端，TASK-020集成，TASK-023/024跨目标验收，无后端互依赖。版本仍0.0.0，未实施新能力，不影响R5历史结论；R6独立审核覆盖本增量。
