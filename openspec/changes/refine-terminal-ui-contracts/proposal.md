# Proposal

## Why

现有规划尚未包含本轮确认的基础输入组件、显式通知更新、视图元素操作、主题配置重载和局部渲染里程碑，且部分旧条款会阻止这些目标。需要将用户共识转为可验收的文本终端契约，先验证语言构造路线，再交由独立审查，避免把宿主图形能力或语言语法糖误当作已实现能力。

## What Changes

- 明确业务处理数据、视图组织呈现、框架调度与渲染；采用持久运行节点＋可重算描述。声明式和动态视图 API 共享子节点序列与生命周期，不替应用决定数据保留、排序或显隐。
- 明确首版文本、输入框、标签、菜单、按钮、单选/复选、进度条、状态栏、模态窗口和分区容器范围；键盘事件为基础，标准编辑快捷键构建于其上。
- 合并响应式与显式定向通知；M1 完整目标帧差分，M2 局部布局/绘制，保持公开 API 一致。
- 按实际行列数布局；最小尺寸不足时按实际尺寸收敛，不自动隐藏；默认纵向滚动，表格允许横向滚动。
- 分类主题配置、四套预置主题、应用主动重载及失败保留旧主题；不引入完整 CSS 引擎或默认文件监听。
- 将本地设备剪贴板、宿主标题和实际图片图标区分为可选会话能力；不向文本终端强加图形支持，不把图标名称当图片图标。
- 在隔离目录验证 SDK 1.2.0 的尾随 Lambda 组合、属性链、回调及绑定边界；调查指定依赖。只将实际证据支持的结论写为已验证。
- 明确Linux、Windows、macOS、HarmonyOS为必需跨平台目标，共用视图API；逐OS/SDK/ABI/终端宿主验证依赖与核心交互，不以交叉编译或OpenHarmony替代HarmonyOS本地运行。
- 同步长期需求、架构、治理、任务与主规格；保留已有文件快照导出，不新增命令行一次性/内联输出模式。

## Capabilities

### New Capabilities

- `theme-config`: 分类主题、预置样式、显式加载/重载与失效传播。
- `terminal-session`: 跨Linux/Windows/macOS/HarmonyOS的字符终端会话、分目标证据、能力报告及可选本地剪贴板/标题/图片图标。

### Modified Capabilities

- `ui-construction`: 基础组件清单、尾随 Lambda 验证路线与统一动态构造。
- `ui-runtime`: 数据与视图职责、通知、布局、滚动、键盘和编辑契约。
- `terminal-output`: M1/M2 渲染阶段及等价性、性能证据。
- `distribution`: 四主题、组件展示应用和必需目标的干净构建/消费责任。
- `development-workflow`: 授权隔离验证、文档与产品验收分离。

## Impact

分类：已确认方向的文档落实属 execution；语言实现、配置格式与动态节点协调的技术细化属 decision，按 design 中替代方案及 R5 证据执行。用户已授权修订规格、提案、必要验证和第三方独立审查。本次只修改规划、证据与必要治理说明，不实现产品，不发布、不创建 PR；依仓库规范审核后直接提交 main。后续产品实施仍需另行授权和 L3 准入。

没有已发布产品 API，故无已发布接口破坏；旧规划条款属于本次显式修订。具体变更任务状态仅由本目录 tasks.md 维护，产品 TASK-001–024 不因本次探针而完成。
