# Capability Specification

状态：需求基线；实现 planned，验证 pending。登记基线不代表产品已实现或变更已归档。

## Purpose

规定终端组件在挂载、更新、卸载以及布局和覆盖层组合期间的可观察行为，使应用状态、显示与交互保持一致，并确保嵌套界面具有确定的生命周期和焦点恢复规则。

## Requirements

### Requirement: 状态与生命周期

框架 SHALL 自动调度可观察状态的内容、样式、布局和显隐更新，合并批量变更；稳定 key 管理身份，卸载释放订阅，后台更新经 UI 调度入口。

#### Scenario: 文本缩短与重排

- **WHEN** 列表重排且绑定文本变短
- **THEN** 节点按稳定身份保留局部状态，残留文本被清除，卸载节点不再接收更新。

### Requirement: 布局与装饰区域

框架 SHALL 区分布局、绘制和交互区域，定义弹性取整、空间不足和祖先裁剪；阴影默认只扩展绘制，不扩大命中区域。

#### Scenario: 窄屏与阴影裁剪

- **WHEN** 嵌套容器缩小且子组件带边框和阴影
- **THEN** 按公开最小尺寸/裁剪规则显示，不产生半个宽字符，阴影不抢占点击区域。

### Requirement: 覆盖层与焦点

框架 SHALL 支持菜单、弹窗及进一步模态确认，定义层所有权、输入隔离、键盘导航、禁用项及关闭恢复；关闭父层同时关闭附属层。

#### Scenario: 关闭恢复

- **WHEN** 关闭模态层时原触发节点已卸载
- **THEN** 选择契约中的有效回退焦点，不访问失效引用，显示底层最新状态。

#### Scenario: 非交互层

- **WHEN** 视觉上层仅用于装饰
- **THEN** 不因其最高显示顺序自动抢焦点。
