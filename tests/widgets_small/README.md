## Additional negative controls and trace recipes

The formal API intentionally has no `Checkbox(true, ...)`, `Radio(true, ...)`, `Progress` text-wrap, or Text-root `.gap` permission. In the independent fixed bundle, compile these as separate **negative consumers** and require the Bool constructor variants to fail type checking and the capability cases to raise `InvalidProperty`; isolate each compile-negative source so one error does not conceal another. This preparation has no declaration stubs or fake product source, so these are not claimed executed.

For S02, record a row for each key with `(target focus, effective enabled, capture, bubble, app, Target, callback count, business value after)`. Required rows include `enter`, `text(" ")`, `text("  ")`, `paste(" ")`, ctrl/alt/shift variants, ancestor disabled, explicit legal unfocused target, capture/bubble/app prevent, capture stop alone, and an onKey business-enabled change with prevent. Expected counts are 0 for excluded/prevented/unfocused/disabled cases and 1 for a valid unprevented Button/unchecked Checkbox/unselected Radio; already selected Radio is 0 and still consumes. Checkbox that only records a request remains `[ ]`. Before callback, Target must have called `preventDefault`; no ancestor default action fires from the same activation.

For S03 style goldens, give the three state layers distinct fixed colors (focused=blue, selected=yellow, disabled=red); then exact resolved foreground under only-focus, selected+focus, and disabled+selected+focus is respectively blue, yellow, red. Set explicit foreground=green to require green regardless of state. Use `Frame.cellAt` structured style rather than ANSI strings. This palette is test data, not a product theme addition.

For S05, mount a Button, save its old `NodeRef`, remove it with public structural commands, insert a *new instance* with the same business model, and assert old ref remains invalid and old cleanup count exactly one. Queue an owner-scoped post for the old generation and verify it does not mutate the new node. Keep the model value unchanged through unmount. The required public hooks are `Component.onMount`, `NodeRef` structure/post APIs, `Application.stats`, and the fixed Runtime generation semantics. The existing `tests/keyboard/pty.mjs` is a transport reference; a dedicated small-widget device consumer and PTY runner must feed actual HT/Enter/Space to `Application.run`, capture raw bytes, exact `stty -g` before/after, sentinel error, exit code, and cleanup marker. Do not claim device coverage from headless dispatch.

`expected.json` is manually edited. `oracle.mjs` only checks fixture shape and three literal anchors; it does not compute product expected values. No renderer or widget helper is imported into the oracle. Test-only changes are limited to this directory. `run.sh` exits 77 until upstream is present, then CJPM and the direct consumer determine true target status.
