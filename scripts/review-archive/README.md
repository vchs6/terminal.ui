# Review evidence archives

`node scripts/review-archive.mjs --root ROOT list` lists groups. Use `resolve LOGICAL`, `verify [GROUP]`, or `restore LOGICAL DESTINATION` after the root option. Restore refuses an existing destination and verifies the complete shard and retained files before publishing. A logical path is repository-relative under `docs/reviews`, or begins with the current root or historical `/workspace/work/terminal.ui/` root. The `mode` returned by `resolve` is the original recorded mode, which `restore` applies. For retained inline files, verification checks regular-file type, size, SHA256 and the user-executable bit; Git checkouts may normalize their other permission bits. Archive member modes and present archive-only originals are checked against the complete recorded mode. Historical checksum lists that name archived files require restoring those files before running `sha256sum -c`.

The separate operator accepts `--root ROOT --group GROUP --keep KEEP.json pack` and then the same arguments with `remove`. KEEP.json is either an array of repository-relative paths or an object `{ "version": 1, "keep": [...], "keepDirectories": [...] }`; paths for the selected group add to its retention set. Review active inputs before packing. Packing also retains Markdown, PNG, checksum files, index/manifest JSON, executable files, the known live X.Org input, literal references and Markdown link targets. It retains at least one tracked descendant of each linked directory and records the decisions in `.archive-v1/retention.json`. Use a complete clean checkout, review the retention report and verify the group before removal. The operator reads Git's tracked inventory but does not stage or commit changes. It never processes an existing `.archive-v1` as input.

Packing creates bounded shards and verifies them before publishing; removal verifies the archive first and rechecks each original immediately before unlinking. Removal may be restarted after interruption. Repeat `pack` after an interruption between publishing the completed archive directory and publishing its catalog entry. Recovery requires the same baseline, unchanged originals, matching retention decisions and successful archive verification. Unknown files are never deleted. If interrupted before the completed directory is published, inspect any abandoned `.archive-v1-pending-*` directory before retrying. Preserve originals until the catalog and verification are complete. This operator must be independently tested on a disposable checkout before any production migration.
