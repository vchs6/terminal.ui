# Review evidence archives

`node scripts/review-archive.mjs --root ROOT list` lists groups. Use `resolve LOGICAL`, `verify [GROUP]`, or `restore LOGICAL DESTINATION` after the root option. Restore refuses an existing destination and verifies the complete shard and retained files before publishing. A logical path is repository-relative under `docs/reviews`, or begins with the current root or historical `/workspace/work/terminal.ui/` root. Historical checksum lists that name archived files require restoring those files before running `sha256sum -c`.

The separate operator accepts `--root ROOT --group GROUP --keep KEEP.json pack` and then the same arguments with `remove`. KEEP.json is either an array of repository-relative paths or an object `{ "version": 1, "keep": [...], "keepDirectories": [...] }`; paths for the selected group add to its retention set. Review active inputs before packing. Packing also retains Markdown, PNG, checksum files, index/manifest JSON, executable files, the known live X.Org input, literal references and Markdown link targets. It records the keep set and linked directories in `.archive-v1/retention.json`. Use a complete clean checkout, review the retention report and verify the group before removal. The operator reads Git's tracked inventory but does not stage or commit changes. It never processes an existing `.archive-v1` as input.

Packing creates bounded shards and verifies them before publishing; removal verifies the archive first and rechecks each original immediately before unlinking. Removal may be restarted after interruption. A packing interruption after the archive directory is published but before catalog publication requires inspection and manual recovery; do not remove originals in that state. Preserve the originals and archive directory until the catalog and verification are complete. This operator must be independently tested on a disposable checkout before any production migration.
