## TASK012 specification and quality assessment

1. **Shared cell semantics and width safety.** `src/frame.cj:38,74,91,171` routes every fill, border and shadow cell through the existing `put` / `clearAt` path. A decoration landing on a continuation removes the whole previous cluster, using the same blank-cell and exact Style semantics as text. There is no parallel screen buffer, Unicode implementation or alternate component painter. Frozen tests `tests/decoration/src/main.cj:56` explicitly replace continuation cells through all three APIs, check styles/neighbor survival, then put wide text over decoration.
2. **Original geometry and bounded clipping.** Each low-level operation intersects iteration bounds with the nonnegative Frame viewport and the supplied ancestor clip before looping; border selection compares original edges, so clipping does not invent corners. Empty frames/rectangles return before virtual-area iteration. Signed addition is saturating for endpoints; negative overflow of a shifted shadow origin returns because even adding any representable nonnegative extent leaves it outside the viewport. Positive-origin overflow is also outside the viewport. `containsAxis` implements shifted-rectangle-minus-original membership without subtracting an overflowing coordinate. Frozen tests at lines 83 onward exercise mixed Int64 extrema, huge extents, negative original geometry and zero-axis huge frames.
3. **Glyph selection and degeneration.** Single/Rounded/Double/Ascii tables match the contract, None is transparent, 1×1 is ASCII plus, and 1×N / N×1 avoid overlapping corners. All six selected border glyph widths participate in whole-set ASCII fallback. Shadow uses `░` only at width one, otherwise `.`. Current public Unicode width policy keeps `░` narrow even in ambiguous-wide mode, so the dot branch has source evidence but no forceable public-policy runtime example; the frozen test and documentation disclose this accurately. No font-detection claim or invented hook was added.
4. **Background, inheritance and paint order.** `src/layout.cj:66` computes inherited text style, paints shadow using its own complete supplied Style, paints the outer allocation only for `Some(background)` (including explicit Color.Default), then border and contents. Border color overrides only border foreground. Noninherited layout/decor fields stay per Component. Content insets combine border and padding and consume left/top first at narrow sizes. Child shadow receives the ancestor content clip, not its own rectangle clip; siblings recursively paint in declaration order. Frozen tests at line 124 onward check allocation, padding, color isolation, exact shadow style, transparent unused cells, Default background covering earlier shadow, clipping, and decoration removal.
5. **User construction and old-area cleanup.** `examples/layout/src/main.cj` builds title / two weighted panels / footer through public Column/Row/Text, property chains and Application callback. It contains no ANSI emission, screen-coordinate arithmetic or flush. Shadow changes do not affect measured dimensions. Callback `d` mutates border/shadow, and the existing Application loop renders a fresh complete target then diffs against its previous successfully written frame (`src/application.cj`, `src/frame.cj:214`). Border/shadow removal therefore restores content allocation and replaces old rows rather than retaining a previous image. Literal target-frame tests and actual PTY tests cover different sides of that guarantee.
6. **Single layout authority.** `render` creates exactly one Frame and one ephemeral LayoutNode tree, recursively measures once, then arranges and paints through one path. Old `measure(Component)` / `draw(Component)` implementations were removed from component.cj. Text validation remains in measure even for zero allocation or fully clipped descendants. The new clip and inset integration does not introduce a second persistent node model. Layout's exact integer quotient/remainder distribution, checked-sum overflow diagnostics, minimum clamping and stable largest-remainder tie order remain aligned with D024 and the independent layout consumer.

No necessary change was identified in this scope. Border drawing currently visits visible rectangle cells rather than only its perimeter; that stays within the explicit bounded-visible-iteration contract, and is not a correctness failure or an invented benchmark gate.
