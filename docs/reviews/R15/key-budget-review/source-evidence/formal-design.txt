135: ## 3. TOML v1 完整语法形状
136: 
137: 首版 schema 的根键 **只有** `schema_version,name,variables,text,decoration,spacing,components,styles`。schema_version 必需为 TOML integer 1，name 必需为非空可打印字符串（去空白后不可空，但保存原文本）；其余可省略。空文件不是默认主题。根表缺失可省略，显式空合法 table 等价无声明。根级 extends/include/import、未知键以及已知键拼错均错误。
138: 
139: 标识符用于 variable/style 名：ASCII `[A-Za-z_][A-Za-z0-9_-]*`，1–128 字节，大小写敏感，不去空格，不允许点/路径/冒号；TOML 引号不放宽语义名称。name 是展示名，不是标识符或文件路径。字面 key、quoted key、dotted key、inline table、普通 table 只要解析后的树完全相同就语义相同，不另建词法解析器。多行字符串按 TOML 解析，但该字段仍受自身值域约束。
140: 
406: T009：输入资源固定预算（不是TOML标准上限）：UTF8≤1048576bytes，variables≤4096、styles≤4096；先复用上游public Lexer.nextToken()对同一不可变输入做预算扫描，再调用原Parser，禁止自己数原字符串括号/点。值容器深度≤16、累计有效键路径≤16段、总tokens≤65536、key/table声明总数≤16384、单key段UTF8≤1024bytes。所有预算同时生效，达到合法，超过ThemeDiagnostic CapacityExceeded。真实token处理字符串/quoted-key/注释，绝不复制TOML词法。有效路径须累计当前绝对table prefix+dotted key+嵌套inline上下文，数组/inline进入离开用显式栈保存路径；不能只限制每局部key段数。此guard只计结构/预算，不解码值、不构建第二语义树、不判重复键，Parser仍负责正式TOML语义。
407: 
408: 上游资源补证表明约1KiB深inline/dotted即可显著占CPU/RSS，1MiB文件限额不足；公开Lexer全部新增样本≤0.033秒并正确忽略四种字符串/注释内括号，故本最小预检有真实必要性。Budget/lexical Err可能先于Parser完整语法错误返回，此时明示token位置，不承诺不安全超限输入也先跑语法。合法预算内仍按6节语法→schema→类型/引用优先。UTF8非法/文件超限在lexer前失败。不得以后台线程timeout假装能终止无界Parser；不引辅助进程、Shell或新依赖。
432: T016（独立测试期SDK语法/预算澄清）：仓颉with是关键字，正式样式builder成员名采用`withValue<T>(key:StyleKey<T>,value:StyleValue<T>,state!:VisualState=VisualState.Normal):StyleRule`，不要求常规调用使用反引号；语义同原候选with，尚无已实现/发布的旧入口，不增加不必要兼容alias。测试作者实际SDK1.2声明-only编译已证明原普通with语法不成立，保留失败原件，不能声称原API已编译。
433: 
434: T009 token预算精确计所有上游Lexer发出的非EOF token，包括CommentStart/其他注释token，EOF不计；空文档是0token但schema仍缺必需字段。声明计数为每次KeyStart、TableStart、ArrayTableStart各1（inline内KeyStart也计），其余token不计声明。边界样本必须用该固定上游public Lexer实数核对，不另写模拟词法；变量/样式4096等预算仍联合生效，避免断言因先撞其他预算而失真。
