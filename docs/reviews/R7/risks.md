本轮是有界调查及顺序调整；不是产品会话、依赖集成或许可批准。开发版本仍为0.0.0。

| 风险 | 已验证事实／处理 | 当前结论及解除条件 |
|---|---|---|
| 非Linux前置阻塞 | TASK-020改为008/017/041；038/039/040在Linux阶段024后启动；023/024先覆盖Linux全部功能 | 顺序已修订。Linux通过不等于跨平台通过；其他目标仍required/pending |
| 可用工具链 | 已有Linux SDK1.2.0正负语言和联合依赖运行证据，本轮继续在Debian13.6/x86_64验证 | 可继续Linux实施；未承诺其他架构/发行版。TASK-001/004仍需冻结实际终端配置 |
| 原生Unicode缺失 | 官方unicode0.1.0包没有build.cj，不会自动生成原生数据；普通build失败不是skip-script所致 | 根因确定。固定UCD17及源码生成C/ASM静态库，并以静态适配库自身FFI声明传递链接的方案已隔离验证，可保留unicode官方清单；正式构建/制品集成仍属TASK-003/023 |
| Unicode算法适配 | 本轮原始库通过Unicode17官方766条GraphemeBreakTest，比较边界和完整码点内容；空串仍产生一个空簇 | 分段路线可保留，薄适配对空输入直接返回空序列。仅代表NFD样本，不声称规范化全量、所有编辑换行或字形一致性 |
| 许可证缺正文 | 已定位四包上游固定commit及许可原文；unicodewidth全包对应仅换行差异，Unicode17数据许可链明确 | 来源缺口部分关闭；最终制品须附归属和许可。ansies/unicode不能称整包逐字节对应所取上游版本 |
| bitarray授权声明冲突 | 原包14个源码/文档/清单文件与固定上游逐字节一致，但README“无。”及许可证项目名/版权归属不一致 | 项目发布许可门槛待核实；不作法律禁止认定，不阻塞内部开发。解除条件：适用于确切源码的清晰授权，或实际移除依赖并验证新路线；不得自己改错字冒充上游授权 |
| TTY与终端差异 | ANSI输出字节、依赖样本和官方协议均不证明键盘、raw mode、resize或恢复 | TASK-041/020必须验证固定Linux控制台及模拟终端；不可捕获终止/永久设备故障限制明确。不把宿主标题/图标/剪贴板列为核心前置 |
| 分发与干净消费 | 本轮不改变主库依赖声明、不把探针库/缓存加入制品 | TASK-023验证实际cjp、构建脚本、依赖FFI、示例/基准与归属完整；只改清单或隔离成功不能记产品通过 |
