# R7 Linux 优先与平台／依赖风险

日期：2026-11-09。基线：533bb9bc645c82cac523a319d0e34ec325fbcc99。

用户明确要求先实施支持 ANSI 转义序列的 Linux 终端，全部完成后才考虑其他平台，随后要求解决平台和依赖风险，并询问是否需要参与。现有规格修订、必要验证、独立审核及直接推送 main 授权继续有效；本轮落实该顺序并做隔离风险验证，不将产品实现或发布记为通过。

分类：顺序调整为 execution，直接落实用户裁决；原生依赖构建及许可证来源为 decision 调查。沿用活动变更 refine-terminal-ui-contracts，新增 TASK-044/045；不另建全项目提案。使用 OpenSpec update-change/sync-specs、Superpowers using-superpowers、systematic-debugging、dispatching-parallel-agents、requesting/receiving-code-review、verification-before-completion。用户已明确修订方向及自主执行要求，不逐文件重复请求确认。

分工：主代理调整阶段和依赖门槛；Sol/high 子代理只读调查及隔离验证 unicode 原生构建；另一 Sol/high 子代理只读核对固定包与上游许可证来源；独立审核者不参与撰写，只依据固定提交和证据审核。只读子代理不得修改产品或历史证据缓存。

用户随后进一步指定测试编写、实现、审核、测试执行和验证由有针对性模型的独立子代理依序完成，互不污染。本轮尚无产品代码，现有探针作者的运行仅为开发证据，另派独立执行者从固定材料复验，并由未参与作者工作的审核者审查；后续产品工作按AGENTS 13.2分离全部五个角色。主代理不代写产品代码或测试。

决策 D-018：选择 Linux 阶段独立闭环，其他平台在 Linux 全部功能、M1/M2、示例、主题、制品及整体验收后进入实施。对比四后端先汇合会阻塞 Linux、取消非 Linux 目标会违背跨平台要求，均不采用。保留同源核心和后端边界；Windows/macOS/HarmonyOS 仍为后续 required。TASK-020 当前仅等待 TASK-041 等 Linux 前置，TASK-023/024 先作 Linux 阶段验收；后续扩展相同验收矩阵，不将 Linux 通过等同于跨平台通过。

Linux 初始验证主机为 Debian 13.6 x86_64、glibc、仓颉 SDK 1.2.0；这是可用验证配置，不承诺所有 Linux/架构/终端均已支持。ANSI 可写不足以证明输入、TTY、尺寸或清理；产品会话验收保持 pending。固定控制台与模拟终端仍在 Linux 必需范围，缺实机证据不能从伪终端或依赖样本推断通过。

风险处理：先查确切包内容和失败根因，再验证干净构建；不复制 Unicode 内核、不改换未获证据支持的依赖、不把元数据等同于分发许可。可逆工程方案由代理依据事实执行；必须改变已确认目标、受限授权或无法取得的设备时才向用户提供具体选项。

审核范围：阶段依赖是否无环且不含非 Linux 前置；保留未来平台目标；依赖构建与许可证证据是否可复现、适用边界是否准确；TASK-044/045 的 DQ01–14；产品 AC 不因风险调查变为 passed。预算：最多三轮修复或六十分钟有效执行。结论只能 design_reviewed 或明确不足，不伪称全部风险已消除。

全量Linux阶段闭合核对：TASK-023还显式等待009（ANSI输入边界）及030（可选会话API/能力报告），避免未交付它们就进入最终制品验收。可选宿主不提供某能力时允许明确unsupported/unknown，不要求全部宿主功能生效。
