# Bounded PTY launcher mechanics audit

- Root cause: running `tests/widgets_small/pty.py` places that directory on the import search path, so `import pty` resolves the fixture itself. Its only required pty member was openpty. Public POSIX `os.openpty()` removes that import dependency without renaming the runner or changing wrapper paths.
- Syntax/help/import surface: actual script `--help` and runpy import completed; the namespace uses the real os.openpty and imports no pty module. Other imported module origins are recorded in import-surface.json. The driver `run` function was not invoked against a helper.
- Real OS transport control: nonproduct Python helper has real TTY fd0/fd1 and controlling terminal, configured6×40 winsize, readiness acknowledgement and bidirectional bytes. Separate normal exit0 and process-group SIGKILL controls record raw input/output/stderr, stty before/after and JSON metadata. Descriptor closure is checked with fstat/EBADF. These are TOOL-ONLY mechanics observations, not widget, native product restoration or product exit proofs.
- FD/launch review: the launcher passes the PTY slave as stdin/stdout, stderr to a regular raw file, and establishes a new session/controlling terminal before exec. The same sequence was exercised by the transport controls. No additional proven pre-execution defect found.
- Metadata review: source binary hash, cwd, mode, stty strings and event dictionary are JSON-compatible; raw bytes are saved separately. Existing exception/finally paths preserve failure metadata and close/reap the child. No metadata/assertion code changed.
- Termination review: child setsid establishes its process group before execution; the guarded killpg/wait fallback is exercised in the tool-only forced-termination control. Product watchdog/input/exit/mode/restore checks remain untouched.
- Output lifecycle: each mode intentionally requires a fresh directory (`exist_ok=False`) to preserve evidence. The earlier AttributeError already created its normal directory; the producer must use a new output path when rerunning. Do not erase/reuse the failed artifact directory.

This audit is limited to import/launch/FD/metadata/termination mechanics. Only the two-line os.openpty correction is warranted. All product behavior assertions and time budgets are byte-equal to baseline; actual three-mode product PTY execution belongs to154 and later independent execution156.
