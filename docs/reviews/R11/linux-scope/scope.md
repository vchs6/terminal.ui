## 可选宿主API与真实证据的不同门槛

核心required：实际字符viewport、键盘/粘贴接收、布局、状态、编辑、层、会话恢复。无图形Linux控制台不因为没有剪贴板/标题/图标而降级核心验收。

REQ-010总体是extension，但TASK030规划了必须交付的安全公共入口/能力结果语义，且028/023需要它。能力三态与操作五态分开：`supported/unsupported/unknown`；`applied/sent_unconfirmed/unsupported/unknown/failed`。无可靠确认的OSC写成功只能sent_unconfirmed。可以在未有实际图片图标官方适配时返回unsupported/unknown；OSC1名称、界面字符或图片显示不能代替宿主图片图标。未修改的宿主状态不恢复；只有保存成功且存在可靠恢复通道才承诺原值恢复。

复制经支持通道指向用户本地设备；SSH上不能执行远程xclip等冒充本地。只写OSC52，不主动查询剪贴板；用户交付的粘贴是输入，括号粘贴整段必须与快捷键分离。当前InputDecoder没有这项能力，不能以“可选剪贴板”免除括号粘贴/编辑验收。剪切复制未确认默认保留选区（refine设计D013已明确）。标题防ESC/BEL注入。上述结果/fallback可本地验证；若宣称SSH/tmux实际生效或标题已应用，则必须提供该路径的真实证据。

物理console属于AC041明确要求而非可选宿主扩展。当前没有证据，必须继续寻找合法实际设备/控制台环境；仅PTY/内存帧/环境变量仿真不足。xterm和VTE已提供两个真实终端实现，追加新能力应在相同体系采集实际效果图、版本、尺寸、场景、代码SHA、原始日志及恢复记录，不能每次重做相同颜色调查。未声称支持的其他任意宿主无需全部测试；待验矩阵项保持pending/insufficient_evidence。

终端限制仍按合同：不承诺字体家族/字号/所有Unicode字形、任意像素图形、完整IME/BiDi、KeyUp或所有修饰键；未知键协议和字形采用公开限制，不以GUI/PTY/Shell实现扩范围。

## 完整 release checker 的具体缺口

`scripts/check-product.sh release`：根build/check；现存examples/benchmarks逐项目build/check/test；强制minimal、composition、benchmarks/rendering三项目有manifest及源；执行rendering的`cjpm bench`；普通`cjpm bundle`；严格check-bundle；干净解包build/check；minimal与composition各`timeout 60s cjpm run -- --smoke`；包内再次`cjpm bench`。不上传发布。

当前静态可确定缺项：**composition和rendering均缺失，minimal没有参数处理/--smoke分支**。不能仅补空manifest或把缺项目从checker移除。普通bundle已经成功但严格bundle检查因composition实际失败。现checker对四主题/展示的存在没有专门required条目，对主题/编辑/层/M2/console的功能也不自动验收；完成这条脚本仍不是AC024的充分证据。应在全阶段具体变更中补与产品清单一致的制品断言/执行入口，同时保留REQ与AC独立核对。

`check-bundle.mjs`检查只含白名单产品文件、禁止链接/特殊文件/越界/开发资料/二进制归档，根依赖来自中心仓、子项目path留在制品内；要求README/LICENSE/NOTICE/product README及上述三项目源码。主题文件可放产品白名单路径，最终以真实包清单与加载运行验证，不能仅看include字符串。

基准不以单测替代：M1固定行列、中文/组合/emoji、局部/批/大范围更新、版本/环境/重复方法；M2额外记录布局节点数、绘制单元数、CPU、分配/内存、输出字节/调用，局部负载减少无关工作且帧等价，大范围变化记录退化成本，无虚构FPS门槛。

## 真正不能由代理自行改变的事项

当前没有需要立刻向用户重新选择的产品问题。技术API、可逆实现、主题解析库/资源上限、依赖准入细化均可按既定Battle/DQ自主决定并记录。

如果实际环境无法提供AC041要求的固定无图形console，不能自行删除该验收或宣称已过；应继续独立功能并保留证据不足，最后如确需新增外部资源/访问权限再说明具体阻塞。若为实现而必须改为普通对象配置替代块语法、取消M2、改成GUI/PTY后端、删某required核心能力或发布，则改变既定目标/授权，不能自主越界。

**许可历史阻塞已被用户裁决解除**：`docs/development/dependencies.md` §6明确“许可证冲突无需由本项目解决，包可用即可”，以及首片design明确保留实际归属、不等待上游声明澄清。不得重新把bitarray冲突设为Linux实施/交付等待条件；不伪造法律许可通过，也不删除真实许可正文。
