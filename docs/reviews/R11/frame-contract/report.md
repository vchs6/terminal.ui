## 一次性列出的需修正项

### S1 / Important：轴长上限破坏既有零面积契约，默认值也需依据与影响说明

- 位置：design.md:11、38；NFR-03（docs/requirements.md:132）；src/frame.cj:8–15；src/layout.cj:274–275。
- 设计明确给出 `maxCells = 1048576`，但只说明“资源有界”必要，没有说明这一具体值的选择依据。NFR-03 明确要求冻结上限时记录依据，不能写无依据数值。
- 这也不只是新增操作的限制：原来能成功构造的 `Frame(1048577, 0)` 现在会报错（旧实现零分配）；`Frame(1025, 1024)` 原先不触发尺寸校验，现在超预算。`render` 内部直接调用默认 Frame，因此同样继承该限制，调用方并无 `render(..., maxCells: ...)`。
- 建议：保留有界保护，不要求恢复无界行为；补充默认值的工程依据（容量目标/支持视口和资源取舍，而非宣称未经测量的内存占用），明确“既有调用/字节不变”限于新合法域。产品说明写明 Frame、render 和应用渲染受同一默认上限约束，以及当前显式预算覆盖适用于低层 Frame。无需扩大本次公开 API。
- **直接兼容冲突：tests/decoration/src/main.cj:84–88 已固定要求 `Frame(0, Int64.Max)` 与 `Frame(Int64.Max, 0)` 可构造，空帧装饰安全且 ANSI 为空。** 原稿“宽/高不得超过 maxCells”会使该旧测试在构造时失败，必须修规格而不能改弱测试。该用例由测试作者在交叉预检中指出，本审核随后独立静态核实。R8 的 1×65536 CUP 证据仍在默认上限内。
- 主代理已提出可行修正方向：预算限制正面积总单元数，零面积虚拟轴保留兼容；所有操作按零面积短路；单独给零宽纯文本的 `height-1` 输出长度设事前预算检查，有限正常高度仍保留旧 LF 语义。应明文写出异常与检查顺序，并涵盖 `copy` 输出帧的零面积情形。该方向不需增加真实巨量分配。

### S2 / Important：文件入口还缺可冻结的创建、替换与失败残留边界

- 位置：design.md:21–22、40；REQ-005.6。
- 字节格式、离线 ANSI 与抛异常方向明确，但没有明确目标不存在时是否创建、已有较长文件是否截断、父目录是否自动创建，以及失败后是否承诺保留旧文件或允许留下部分内容。不同合理标准库调用会产生不同可观察结果；独立测试作者不应自行选择这些公开行为。
- 建议冻结最小契约：新文件创建；已有文件替换且截断到准确长度；不自动创建父目录；所有实际打开/写入/关闭错误向调用方传播；失败可留下不完整文件，不承诺原子替换或旧文件保留。若选择其他策略，也应明文写出。
- 文件异常不必冻结平台具体消息或每种路径的精确子类；可以规定传播标准库文件/I/O 异常。测试至少应核已有更长文件、零字节快照截断、确定失败路径；仅测试缺失父目录不能代表写入阶段失败覆盖。以目录目标、缺失父目录或适当 Linux 写失败设施设计稳定场景，避免 root 下 chmod 权限用例假失败。
- 这不是要求新增事务文件系统或持久化保证，也不要求完成 TASK-010 的应用层捕获。

## 已核实可实施、无需新增阻塞的部分

| 维度 | 结论与实现/验证边界 |
| --- | --- |
| API 与组织 | Frame/Cell 已在 cjtui；Rect 通过 exports.cj 公共导出。新增命名默认参数与既有调用方式一致。无需新 overlay 帧类型或第二字符/样式/ANSI 内核。Cell 为不可变值字段，独立数组复制即可避免可变 cells 别名。 |
| 透明与空白 | 显式 isTransparent 能区分默认样式空格与“不绘制”。透明单元规范化规则充分；put/fill/装饰的实际写入不透明；清除伙伴使用目标默认空白类型有明文规定。 |
| 源宽簇裁剪 | copy/resized/composite 将被切开的不透明源片段转成同源样式单列空格，保留 styled background 并消除孤立 continuation。它不改变 put 原有“裁掉整簇但继续定位后续文本”的行为。 |
| 目标宽簇覆盖 | 允许清除几何交集外的伙伴，是维护完整字符簇的必要例外；源透明不触发实际写入，因而不应清除目标。设计两条合读可得唯一结果。 |
| 自身重叠 | 操作开始时源快照规则充分；实现应复制 Cell 数据，不通过重跑 put/resegment 构建快照。layer 与目标为同一实例时，源保持不变应理解为读取视图保持原内容，最终目标当然发生变更。建议可加一句消除字面歧义，非阻塞。 |
| 策略不匹配 | ambiguousWide 不同在任何修改前拒绝，copy/resized 保留策略。按该明确规则，即便无交集或零面积也可先拒绝不匹配；可加测试固定这一顺序，非新增路线问题。 |
| 坐标与预算 | Rect 非负宽高；裁剪后的有限范围可限制循环，不能迭代未裁剪巨大 rect，也不能对 Int64.Min 做不受检取负/相减。面积预算与零宽纯文本输出预算应分离，避免破坏既有空帧虚拟轴契约，见 S1。copy/resized 继承预算和默认空白类型可实施。 |
| 字节兼容 | 普通有限合法帧可保留所有旧 toPlainText/toAnsi 字节；无需透明专用 ANSI。旧 contract 明确的 full-column 空格、行间 LF、无尾 LF/ESC、CUP 与初尾 reset 均继续有效。Frame(0,2).toPlainText() 现为一个 LF，设计的保留规则应继续适用，不能统一把所有零面积纯文本改成空串。 |
| 快照 | 文件消费完整帧而非差分，TrueColor 离线默认与既有 toAnsi 一致；无需终端探测。可直接复用标准库文件路径，既有仓库测试已使用 File.writeTo(..., text.toArray())，没有新依赖风险证据。 |
| 上游与阶段 | R8–R10 的已验 Frame/Unicode/Style 加当前具体子接口可作为 L002 分阶段输入；不要求完整 001–004 关闭。005/007 的帧 AC 可独立关闭。010 可见应用层/018 汇合与最终 Linux/release 仍待后续，文档没有提前宣称通过。 |
