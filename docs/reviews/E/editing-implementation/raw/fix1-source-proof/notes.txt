I01: Binding getter tracking prohibits normal Observable.notify during evaluation. Only the editor source binding installs the optional internal afterEvaluate hook. It runs after successful track and subscription with evaluation guard restored; default None leaves all other bindings unchanged. The hook flushes the currently mounted editor's pending private signal; it neither schedules a new queue nor calls user code. Non-getter sync flushes normally. A failed track or flush propagates through existing owner-session failure/cleanup; unmount clears owner.session and a new mount creates a fresh editor session.
I04: handle.sync takes the existing atomic value/version snapshot and projects it before capturing sourceVersion. Text/paste/Enter/backspace/delete pass that captured value through keyboardInput/range calculation into replace as preparedVersion; that path cannot re-sync to a later value. The existing commit helper passes the captured version to Observable.editingCommit, whose failed comparison is the sole ConcurrentValueChanged issue locus. No source lock is held during Unicode work or user callbacks.
No-op: when planned text is identical, guarded/prepared paths compare actual source version before selection-only publication; a stale prepared operation projects the external update and returns false without applying its old selection intent or writing the source. Rejection: invalid input and byte-budget checks use the prepared local text/selection and return after their issue, before replace or a source write; subsequent external projection follows ordinary synchronization. onIssue itself remains application code and may write the source.
The public worker test observed a conflict without stale overwrite, but does not force or time the earlier planning interval; that interval is established here by source inspection, not claimed as an executed deterministic race.
