# Linux 阶段完成计划

> For agentic workers: 按 Superpowers subagent-driven-development 执行；本文是总调度索引，不重复维护稳定 TASK 复选框。

**Goal:** 完成当前支持 ANSI 的 Linux 终端全部约定功能、M1/M2、公开示例、基准、完整源码制品及独立整体验收。

**Architecture:** 保留仓颉组件块、属性链及单一 Component/Frame/Style/Unicode/ansies 路径。补齐可观察状态、持久身份、UI 调度、焦点与层管理，M2 对照同一 M1 参考帧。宿主扩展独立返回真实支持/结果，不成为核心启动前置。

**Tech Stack:** 仓颉 SDK 1.2.0，现有 ansies/unicode/unicodewidth；宏与主题解析的新构建前置须经真实正常消费者验证。产品版本 0.0.0。

**Spec:** requirements.md、architecture.md、ui-construction.md、theme-config.md、terminal-session.md；具体接口以各实施变更 design 为准。全部状态权威仍由 tasks.md 及其转移引用维护，实际 AC 由 acceptance.md 维护。

## Global constraints

- 用户本次明确要求完成全部 Linux 工作，延续自主技术裁决、独立角色及 direct-main 授权；不在单个有限增量结束后把全阶段任务搁置。
- 主代理只负责契约、计划、调度、集成和分歧处理；测试编写、产品实现、审核、执行与验收各自独立上下文/目录。使用 Sol 测试、Terra 或适合仓颉语言的 Sol 实现、Astra 整片审核/验收、Sol medium 确定命令执行，按实际可用模型记录指定配置。
- 每个仓颉类、结构体、接口、枚举单独文件，按职责与 package 组织；保留已冻结公共调用，废弃私有路径明确退役，不增加第二渲染/宽度/ANSI 内核。
- 既有 R8/R9/R10 有效证据按相关内容、环境、依赖及范围复用；功能变化补受影响测试，阶段集成与最终 release 执行完整必要检查，不因文档提交机械重复冷套件。
- 产品不依赖 JS/TS、GUI、Shell 执行、完整终端模拟器或 CSS 引擎。测试宿主/采集工具仅为开发验证依赖。
- 保留第三方实际许可/归属；用户已裁决不以许可声明冲突阻塞包的实际使用。不自动 publish。
- 使用真实不同终端实现验证并保存原始运行 PNG、版本/尺寸/源码/时间/hash/raw。未知环境不伪装通过，TERM 仿真只算分支测试。
- Windows/macOS/HarmonyOS 为后续目标；当前不以其为 Linux 完成前置。

## Review focus

1. 动态 key 重排、手动插入与卸载不能形成两份子序列、失效引用或订阅泄漏。
2. 粘贴是数据，不能把其中 Enter、ESC 或 Ctrl-C 当业务快捷键；复制失败的剪切不能删除选区。
3. 裁剪、覆盖、移动与局部重绘必须保持字符簇完整，透明与不透明样式空格区分。
4. 主题失败/旧请求不能部分覆盖已接受主题，不重建编辑、焦点和业务状态。
5. M2 与 M1 结果逐帧相等；基准同时报告实际布局/绘制工作、CPU、分配与输出，不以行差分冒充局部布局。

## 依赖裁决

- **Ruling L001:** 014 的“可复用构造契约”先作为 015 输入；同组件用于弹窗的原 AC 在 018 后补齐。保持 014 原验收要求，避免 014→018→016→015→014 的语义环。
- **Ruling L002:** 001–004 按可定位的接口/平台输入分阶段交付，下游可以消费已冻结部分；不把上游完整 AC 提前判通过，也不让最终真实 console 证据反向阻塞与其无关的帧/状态实现。
- **Ruling L003:** 保留当前支持 ANSI 的 Linux 范围和字符语义。物理 console、复用器等实际环境不足时继续其他工作并有依据寻找可运行环境；最终未获得的必需证据须如实列为不足，不能用环境变量代替。
- **Ruling L004:** 优先原生尾随 Lambda 与已实证宏、标准仓颉构建；不新增语言运行时或手写完整 TOML/Unicode/ANSI 内核。宏 @Component/@State/@Bind 的精确源码与支持限制在运行时变更冻结。
