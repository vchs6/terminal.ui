# cjtui 终端会话与可选宿主能力

本文细化 [REQ-010](requirements.md) 与 [terminal-session 场景投影](../openspec/changes/refine-terminal-ui-contracts/specs/terminal-session/spec.md)。会话、适配器和下列接口语义均 planned/pending；协议资料只证明协议含义，不证明 cjtui 已实现，也不证明所有终端均支持。

## 1. 基础会话与能力边界

核心界面以当前终端实际行列数、字符显示、键盘事件、布局与刷新为基础，不要求窗口系统、字体 API、图形或剪贴板。会话统一拥有设备输入、屏幕输出、模式和资源生命周期；组件回调通过受控入口请求能力，不直接输出 ANSI 或执行系统命令。TTY、raw mode、resize、取消及异常的受支持平台矩阵由 TASK-001 调查、TASK-004 冻结；不得从当前 Linux CI 推导全平台支持。

| 能力项 | 目标语义 | 范围 |
|---|---|---|
| 字符 viewport、键盘、布局和更新 | 在实际行列范围组织交互界面 | 核心必需 |
| 本地设备复制 | 发送文本到终端使用者的剪贴板；SSH 时仍指用户本地设备 | 可选宿主通道 |
| 粘贴文本接收 | 用户操作终端后接收其投递的文本/括号粘贴事件 | 输入能力；不主动读剪贴板 |
| 宿主窗口/标签标题 | 请求宿主设置标题字符串 | 可选宿主通道 |
| 实际图片图标 | 设置宿主自身的图片图标，例如其窗口或标签所用位图 | 可选、逐宿主验证 |

实际图片图标不是 OSC 1 的 icon name，也不是文本界面里的图片。当前没有本项目已验证的图片图标适配器，不预设具体通用协议；这不扩大字符渲染后端到图片显示、像素画布或图形窗口框架。

## 2. 能力与操作结果

每项能力分别报告 `supported / unsupported / unknown`，附依据：已验证的平台适配、终端配置、协议协商结果或应用显式覆盖。终端名称、环境变量或成功写入可作线索，不能单独当作宿主效果确认。用户覆盖是使用意图与环境声明，不消除真实写入失败或宿主拒绝的可能。

| 操作结果语义 | 可作的陈述 |
|---|---|
| 已确认生效 `applied` | 存在可靠宿主确认或直接宿主 API 的已验证成功语义 |
| 已发送但未确认 `sent_unconfirmed` | 输出完整写入，缺少宿主效果确认；OSC 类操作常落在这里 |
| 不支持 `unsupported` | 当前配置或已验证平台明确不提供能力，没有发起假替代操作 |
| 未知 `unknown` | 无充分依据确认通道可用；返回给应用，由其决定提示或配置 |
| 失败 `failed` | 校验、通道、部分写入、适配调用或恢复出现可识别错误 |

表中是待冻结的结果语义，不是已存在的仓颉枚举。报告项必须含操作类型、能力依据与必要错误原因。可选操作的失败不得伪装成功，也不得仅因不支持就停止核心界面；如果实际设备写入同时破坏了输出同步，则按统一输出失败契约处置并报告，不为维持界面虚称恢复。

## 3. 本地设备剪贴板与粘贴

复制由用户动作或应用显式调用发起，文本通过已声明可用的 OSC 52 或已验证等效通道发送。SSH/tmux 等路径的透传和终端权限可能阻止到达本地设备，需分别记录支持证据。框架不自动执行远程 `xclip`、`wl-copy`、`pbcopy` 或 PowerShell 命令并声称改变用户本地剪贴板；没有可用通道时返回不支持或未知，应用可提示文本选择等替代操作。

框架不主动发送 OSC 52 的 `?` 查询，不读取本地设备剪贴板。粘贴由终端用户操作触发，通过输入事件接收；括号粘贴内容作为一段文本处理，不能把其 ESC 或换行逐个当作快捷命令。未提供括号粘贴标记时只能按已公布输入规则解析，不保证能区分键入与粘贴来源。多行文本进入单行输入框时的截取/拒绝策略归 [键盘与编辑要求](requirements.md) 及组件契约，不能由剪贴板层静默改写。

剪切对本地文本的删除须遵守输入组件事务：复制不支持或失败时不得悄悄删除选区；已发送但未确认的后续处理由编辑契约明确，不把未确认当成可靠系统剪贴板提交。通道负载上限、UTF-8/Base64 编码、超限诊断、跨块输入与取消清理必须在平台契约中冻结；不可截断后仍报告完整复制。

[XTerm 控制规范](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html)（Patch #411，2026-08-23，核对于 2026-11-09）定义 OSC 52 写入/查询，并受 selection 权限配置约束；本文选择只写入、通过用户输入接收粘贴。[XTerm 括号粘贴说明](https://invisible-island.net/xterm/xterm-paste64.html)解释模式 2004 与输入分隔；这是终端投递协议，不是读取本地剪贴板接口。

## 4. 标题与实际图片图标

标题由应用显式请求，经统一后端在已声明 OSC 2 或等效宿主通道下设置。参数不得包含 ESC、BEL 等控制字节；首版拒绝并定位非法输入，避免设备控制注入。使用前记录能力与是否支持原值保存/恢复，不把设置标题连带成修改图标或全局终端配置。

实际图片图标独立报告能力。实现前必须具备宿主官方接口、图片格式/大小约束、调用方式及失败/恢复证据；没有适配器就返回 `unsupported` 或 `unknown`。不能拿图片显示协议、Unicode 图形、OSC 1 名称或“发出字节”满足图片图标验收。

[XTerm 控制规范](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html)明确区分 OSC 1 图标名称与 OSC 2 窗口标题，不能据此推导实际图片图标支持。本次工程选择按能力提供可选适配入口；相比强行要求所有文本终端支持图片或用名称冒充位图，该方案保持用户明确的字符终端基础。具体宿主适配尚待证据，不增加图形宿主依赖。

## 5. 退出与恢复

会话记录由框架实际开启/修改的模式和可恢复状态。正常退出、取消及可处理异常进入同一清理路径；尽量完成独立清理项，并逐项保留失败结果。未由框架修改的标题、图标及其他宿主状态不主动覆盖。

标题/图片图标只有在通道确实支持保存或获取原值、保存成功且框架已修改时才承诺恢复；可以使用有明确语义的宿主保存/恢复栈，不要求必须读取标题字符串。缺少这些条件时预先报告无法保证恢复，不能在退出时发送某个默认标题并声称原值已恢复。恢复写入成功但无宿主确认时同样只能报告已发送未确认。

核心终端模式按已验证平台清理：输入模式、括号粘贴、光标、备用屏幕及已登记资源。原值未知时明确记录所能执行的清理动作与限制，不能推断已恢复到任意用户原始配置。设备永久失效、进程被不可捕获终止等情况不承诺必然恢复；这不免除正常、取消和可处理异常路径的恢复责任。

## 6. 待实现验收

| 场景 | 可观察结果 |
|---|---|
| 没有图形、剪贴板和标题能力 | 核心文字界面正常运行，可选请求明确返回结果 |
| SSH 下复制 | 目标为用户本地终端，记录传输通道，不运行远程系统剪贴板替代 |
| 终端忽略 OSC 输出 | 只报告已发送未确认；不能断言本地状态改变 |
| 多行括号粘贴含快捷键字符 | 进入有效文本输入目标，不触发逐键业务命令 |
| 图片图标无宿主适配 | 不支持或未知；不能改发 OSC 1 冒充 |
| 原标题可保存且已修改 | 退出执行受支持恢复，记录确认程度及失败 |
| 原标题未知或恢复失败 | 结果明确不可保证或失败，其他清理继续 |

本次协议调查没有真实终端集成、GUI 图标适配或 SSH/tmux 实测结果。后续平台矩阵须记录具体终端、版本、连接路径、权限与确认方法，不能以规范文档替代产品验证。

## 7. 必需跨平台目标

REQ-011将Linux、Windows、macOS、HarmonyOS列为必需目标；当前仅Linux x64有隔离语言/依赖探针，四平台产品支持均planned/pending。矩阵必须分别定位OS/CPU/ABI、目标SDK/运行库、终端宿主、权限和连接路径。OpenHarmony不与HarmonyOS互换，鸿蒙作为SSH客户端连接Linux不算应用在鸿蒙运行。

平台适配须验证输入事件、字节/文本编码、固定或变化尺寸、完整/部分写入、模式/取消/恢复及安全诊断。不能因某API名类似POSIX就假定应用沙箱可调用；图形应用日志或非交互shell不满足字符UI。外部终端宿主可作为运行前置，cjtui不因此实现图形窗口/PTY。四目标均有至少一个冻结配置运行核心场景后，才能声明完整跨平台支持。剪贴板、标题、图片图标仍独立按能力报告，缺失不影响核心支持结论。
