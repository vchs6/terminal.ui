# cjtui 主题配置设计

本文细化 [REQ-008](requirements.md) 和 [theme-config 场景投影](../openspec/changes/refine-terminal-ui-contracts/specs/theme-config/spec.md)。这是待实现设计；公共仓颉签名和完整配置 schema 在 TASK-004 冻结，本文中的 TOML 只示意数据组织，不是已可加载的产品配置。

## 1. 配置边界与工程决定

用户已确定分类主题、四套预置、应用显式重载、失败保留旧主题；本变更将这些方向落实为文档，不启动产品实现。格式与复用方式属于代理可裁决的可逆工程细化。

| 方案 | 收益与代价 | 决定 |
|---|---|---|
| 单个 TOML 文件，变量与命名样式复用 | 人可编辑；静态类型校验、引用解析及诊断范围清楚 | 代理选定的首版方案；解析依赖与 SDK 兼容性待实施准入时验证 |
| 多文件 `extends` 继承 | 可拆包复用，但要引入路径解析、循环、覆盖及发布边界 | 首版不支持；出现 `extends` 或 `include` 明确报错 |
| CSS 选择器与级联 | 表达力强，但超出分类配置的目标并增加另一套规则 | 不采用 |

命名样式只按名称由组件显式引用，不扫描组件树、不匹配选择器、不执行表达式或脚本。变量为带类型的静态值，可供属性引用；变量之间首版不允许互相引用，避免隐式求值图和循环。配置文件路径由应用显式提供，不按工作目录搜索其他主题，不请求网络资源，不展开环境变量或执行代码。

这是决策型细化的单代理 Battle：挑战“单文件是否不能复用”的反例由变量和命名样式解决；挑战“无继承是否限制分发”由独立完整主题文件解决；挑战“重载是否改变业务状态”由事务只替换样式值解决。结论不引入跨文件继承；风险是大型主题有重复，出现真实维护证据或配置迁移需求时重新审查。正式决策汇总归入本次变更 design，本文不维护任务状态。

## 2. 分类与单位

| 分类 | 可配置内容 | 边界 |
|---|---|---|
| 文本 | 前景/背景、粗体、下划线等已公布终端属性、换行/截断/文本对齐 | 不设置字体家族、字号、字距，不加载字体 |
| 装饰 | 字符边框、离散圆角样式、字符阴影与颜色 | 阴影默认扩展绘制区，不扩大布局/命中；服从裁剪 |
| 间距与对齐 | 内边距、组件间距、水平/垂直对齐及已支持尺寸约束 | 横向显示列、纵向行；非负整数间距，不使用像素 |
| 组件 | 首版各公共组件的默认外观与命名样式 | 不保存事件回调、业务对象或数据源 |
| 状态 | 正常、聚焦、选中、禁用的属性覆盖 | 只读取组件已有状态，不设定业务选中项、不禁用业务动作 |

合法但终端无法显示的效果按能力策略降级；不存在的属性是校验错误。RGB 映射到 256/基础色时保留原始结构化主题值，以便后端切换能力后重新解析；不通过 OSC 4 等操作改全局调色板。字形覆盖不可靠时报告未知，支持显式 ASCII 回退配置，不能把单个终端的字形当成通用保证。

## 3. 逐属性解析

来源顺序固定为组件显式属性 > 可复用样式 > 活动主题 > 框架默认。每个属性单独解析，设置前景不覆盖另一来源的背景。组件声明多个命名样式时，后声明者只覆盖其实际设置的属性；组件显式属性继续优先。

同一来源内，逐属性按禁用 > 选中 > 聚焦 > 正常查找；某状态未设置该属性就继续查下一个活动状态。例如同时选中与聚焦时，选中前景优先，但未设的背景可取聚焦背景。上述顺序为本轮代理工程决定；主题不得用外观覆盖改变组件交互语义。

“未设置”表示继续回落；“显式复位”表示直接使用该属性的框架默认，不继续使用低优先级来源。移除复位后重新按来源查找。父子间只允许公开列明的文本属性默认传播，布局、尺寸、边框、内边距和阴影不自动继承；组件对子项的主题默认与父样式继承须分开记录。

配置组织示意（字段名未冻结）：

```toml
schema_version = 1
name = "example-dark"

[variables]
accent = "#66CCFF"
surface = "#101820"

[text]
foreground = "#E8EDF2"
background = { ref = "surface" }

[decoration]
border = "rounded"

[spacing]
padding_columns = 1
padding_rows = 0

[styles.emphasis]
foreground = { ref = "accent" }
bold = true

[components.button.states.focused]
underline = true

[components.button.states.disabled]
foreground = "#808080"
```

变量引用类型必须与属性一致；未知变量、未知组件/状态/属性、非法范围、重复定义或不支持 schema 版本均为错误。允许省略的属性按解析顺序回落；不能因有默认值就吞掉拼错字段。诊断至少给文件、键路径、错误原因和可取得的行列位置；无精确位置时明确范围，不虚构坐标。完整属性列表、布尔/枚举/颜色取值及复位序列化形式仍由 TASK-004 冻结。

## 4. 加载、切换与重载

应用选择预置主题或提供外部文件路径，主动发起加载/切换/重载。框架默认不启动文件监听器；应用可自行检测文件变化，再调用同一公开重载入口。

候选配置先在活动主题之外读取、解析、校验及解析引用，整套有效后才投递至 UI 执行域。在一个更新批次中替换活动主题版本、使相关样式缓存和绘制失效；尺寸或间距变化使布局失效。输出帧不能混用同一组件的新旧主题。期间业务数据、焦点、选中项、输入内容和节点身份不因主题替换被重建。

读取失败、语法/引用/属性错误或 UI 会话已关闭时返回可诊断失败，保留活动主题和界面。成功仅指配置接受及替换，设备输出仍受统一输出错误契约约束，不能把加载成功当成终端已显示成功。应用发起请求时分配顺序标识，UI串行提交；较早请求较晚完成时不能覆盖已接受的新请求，每次报告对应结果。实现冻结时确定取消与请求编号的具体签名。

## 5. 预置主题与验收

| 主题 | 风格方向 | 验收重点 |
|---|---|---|
| 深色 | 深底浅字、克制强调色 | 文本、背景与焦点对比 |
| 浅色 | 浅底深字、清晰边界 | 不能直接机械反转所有颜色 |
| 高对比 | 强对比并配合字符/文本状态提示 | 不只靠颜色区别聚焦、选择和禁用 |
| 经典终端 | 基础终端色与简洁字符装饰 | 在基础色/ASCII 回退下仍可辨识 |

同一展示应用覆盖文本、输入框、标签、水平/弹出菜单、按钮、单选/复选、进度、状态栏、分区容器和模态窗口；各主题切换同一组组件和数据。展示正常、聚焦、选中、禁用及其组合，含窄屏、Unicode 装饰和 ASCII 回退。不得以四份不同业务逻辑或主题专用内核特判掩盖差异。

验收包括：逐属性冲突与复位、全部主题切换、仅颜色重载、改变间距的重载、文件修改但不主动重载、非法文件保留旧主题、模式降级不改调色板。展示应用和产品主题文件尚未实现；这些是后续交付要求。
